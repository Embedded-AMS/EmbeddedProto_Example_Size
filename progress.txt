# Size Comparison Tool - Progress Log

## Codebase Patterns
- The project uses CMake for building both desktop and embedded targets
- Existing build.sh script handles code generation and compilation
- STM32 project exists in F446RE_EmbeddedProto/ directory with STM32CubeIDE-generated makefiles
- Symbol tracking and map analysis tools already exist
- EmbeddedProto, NanoPB, and ArduinoJson are available as submodules
- ARM toolchain is located in STM32CubeIDE plugins directory (e.g., /home/bart/st/stm32cubeide_1.4.0/plugins/com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.*/tools/bin)
- Build configuration uses -Os optimization and gc-sections for size optimization
- The Release/ and Debug/ directories contain pre-generated makefiles from STM32CubeIDE
- ARM toolchain detection should use glob patterns to find tools in STM32CubeIDE plugin directories
- ELF size extraction uses Berkeley format output from arm-none-eabi-size (text, data, bss columns)
- STM32 flashing uses OpenOCD with interface/stlink.cfg and target/stm32f4x.cfg configs
- DWT cycle counter for Cortex-M4: enable TRCENA in DEMCR, then CYCCNTENA in DWT->CTRL
- UART output via ST-Link VCP on /dev/ttyACM0 at 115200 baud
- Use pyserial for serial port detection and communication
- STM32 firmware runs once at startup - use OpenOCD reset to trigger new measurement
- Test scenarios are in scenarios/<name>/ with message.proto, test_data.json, expected_wire.bin
- NanoPB options file uses dot notation: package.Message.field max_size:N
- EmbeddedProto strings use mutable_field().set(data, len) not set_field(string)
